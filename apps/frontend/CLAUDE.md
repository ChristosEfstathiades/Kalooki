# CLAUDE.md (apps/frontend)

Frontend-specific guidance for the TanStack Start app. Repo-wide context, commands, and coding conventions are in the root `CLAUDE.md`.

- **Routing:** file-based routes in `src/routes/` (`__root.tsx` is the shell). `routeTree.gen.ts` is **generated** by `tsr generate` — do not edit it by hand. Router/query setup lives in `src/router.tsx` and `src/integrations/tanstack-query/`.
- **Two pathless layouts wrap almost everything.** `_app` is the chrome (announcement banner, header, footer); `_app._auth` nests inside it and is the signed-in guard — its `beforeLoad` redirects to `/signin` without a stored token, and it holds the socket subscription that navigates to a match when one starts. Public pages are `_app.*` (`rules`, `tips`, `contact`, `privacy`, `signin`, `signup`, `verify-email`), signed-in pages are `_app._auth.*` (`play`, `history`, `leaderboard`, `settings`). `index.tsx` (welcome) and `game.$matchId.tsx` (the table) sit **outside** `_app` on purpose — neither wants the header/footer chrome.
- **UI:** Tailwind CSS v4 (configured in `src/styles.css`, not a `tailwind.config`) with shadcn/ui components (new-york style, `zinc` base colour, CSS variables) in `src/components/ui/`, built on Radix UI with `lucide-react` icons. Add components per `components.json`. Game-table pieces are in `src/components/game/`, chat in `src/components/chat/`, friends/groups dialogs in `src/components/social/`. Drag-and-drop (hand rearranging, laying melds) is `@dnd-kit`.
- **Backend client:** `@tuyau/core` consumes the type-safe client the backend generates, so **the backend must be built before this app typechecks**. `src/lib/api.ts` creates the singleton and attaches the bearer token on every request; `VITE_API_URL` overrides the `http://localhost:3333` default.
- **`src/lib/` is one module per domain** (`auth`, `game`, `chat`, `presence`, `social`, `moderation`, `stats`, `news`, `site`, `preferences`, `theme`, …), each owning its queries and socket subscriptions — put new data access there rather than in components. `src/lib/socket.ts` is the single Socket.IO connection; `src/lib/auth-token.ts` owns the token under `kalooki.accessToken`, in localStorage for "remember me" signins and sessionStorage otherwise (read in that order).
- **SEO:** every route builds its head through `seo()` in `src/lib/seo.ts` (title, description, keywords, robots, canonical, Open Graph/Twitter, optional JSON-LD). Signed-in pages pass `noindex: true`; `_app/_auth` also sets a blanket noindex so a new authed route is covered by default. The public pages are listed once in `sitemap.ts` — that list drives both the build-time prerender (`pages` in `vite.config.ts`) and the generated `sitemap.xml`, so adding a public page means adding it there. The site origin comes from `VITE_SITE_URL` (falling back to `https://kalookionline.com` in both `seo.ts` and `vite.config.ts`).
- **Security headers:** `security-headers.ts` (app root, beside `sitemap.ts` — both outside `src/` because `vite.config.ts` imports them) builds the CSP and header set, applied by Nitro `routeRules` on **builds only**; the dev server's HMR channel does not fit a policy that tight. `connect-src` is derived from `VITE_API_URL` and includes the matching `ws:`/`wss:` origin for Socket.IO, so **talking to any new external host means editing that file** or the browser blocks the request in production while dev looks fine. Its spec and `sitemap.test.ts` are the app's only Vitest tests.
- **Import aliases:** `#/*` and `@/*` both map to `src/*`.
