# CLAUDE.md (apps/admin)

Guidance for the admin app. Repo-wide context, commands, and coding conventions are in the root `CLAUDE.md`.

The admin-only site served from `admin.{domain}` (dev: port 3001). It is a **plain Vite + React 19 SPA** — not TanStack Start, which this app has no use for: no SSR, no file routes, no nitro.

- **Sections and routing:** eight sections (overview, reports, users, chat, audit, news, settings, stats), listed in `#/lib/router`. Routing is a **hand-rolled hash router** in that file (~60 lines: `useAdminSection`, `sectionHref`) rather than a routing library — the sections need to be deep-linkable and survive a refresh, and nothing beyond that. Add a real router only if nested layouts, loaders or route-level code splitting become necessary. `DashboardPage` maps the section to its page and owns the user dossier dialog, since reports, chat and users all open it.
- **Data layer:** one module per section under `src/lib/` (`reports`, `metrics`, `chat-browser`, `news`, `settings`, `stats`, plus `admin` for users and the audit log). The report queue, metrics and dossier shapes are computed aggregates rather than model transformers, so they are **not** in the generated `Data` namespace — each module names its fetch function and derives its row type from it (`Awaited<ReturnType<typeof fetchX>>['rows'][number]`) so types still flow from the backend.
- **Charts:** `TrendChart` is inline SVG, no charting library. Its two series colours are `--color-chart-*` in `src/styles.css`, picked against `--color-panel` (the UI accents are too dark to read as data marks) and validated for colour-vision separation. If you add a series, validate the palette rather than eyeballing it.

- **Why it is separate from `apps/frontend`:** so no admin code ships in the bundle players download, and so the two sites are separate origins with separate sessions. The security boundary is `middleware.role('admin')` on `/api/v1/admin` in the backend — the separate build is defence in depth, not the control.
- **Auth:** signs in through the shared `/api/v1/auth/login`, then refuses any account whose role is not `admin` and discards the token. Its token lives under `kalooki.admin.accessToken`, a different key from the player site's, so the two sessions never collide on `localhost` in development.
- **Backend client:** the same generated Tuyau client the frontend uses (`@KalookiOnline/backend/registry`), so the backend must be built before this app.
- **Styling:** Tailwind v4 with a small self-contained theme in `src/styles.css` — deliberately colder and denser than the player site's card-room palette so the two are never confused. Dark only. There is **no shadcn/ui here**; `Button`, `StatusPill`, the `Field`/`TextInput`/`Select`/`Checkbox`/`Toggle` form primitives, `StatTile` and `Pagination` are the whole component library, and dialogs are plain fixed-position markup. Keep it that way unless the app grows enough to justify more.
- **Import alias:** `#/*` maps to `src/*`.
